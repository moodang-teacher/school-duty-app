# 2026년 10월 배정 기준

- 2026-09-30까지의 배정은 수정하지 않는다. 재생성 시작일은 요청일, 한국 기준 현재 날짜, 2026-10-01 중 가장 늦은 날짜다.
- 발표된 일정이 현재 제외 조건을 만족하고 보정 누적 횟수가 균등한 범위에 있으면 선생님별 총횟수를 유지한다.
- 신규 참여자는 참여 이전의 당직을 보충하지 않는다. `teachers.dutyStartDate`에 최초 참여일을 저장한다. 기존 명단에 값이 없으면 최초 순환에 포함된 교사는 연초 참여로, 나머지는 최초 배정 및 `swappedFrom` 기록으로 추정한다. 정확한 참여일을 알고 있으면 명시적으로 입력한다.
- 참여 이전 이력으로 보정 횟수를 계산하므로 첫 근무 후 재생성해도 보정이 사라지지 않는다. 연도가 바뀌면 해당 연도 기준으로 계산한다.
- 총횟수를 유지하며 날짜를 교환해 요일별 횟수의 제곱합, 연속 당직과 짧은 근무 간격을 줄인다. 제외일과 고정 교환이 우선이므로 모든 조건에서 완전 균등이나 최소 간격을 보장하지는 않는다.
- 2026년 요일 분포는 10월부터 계산한다. 9월 이전 편중을 한꺼번에 보충하지 않는다. 다음 연도부터는 연초가 기준이다.
- 승인된 교환은 날짜와 메타데이터까지 고정한다. 교환과 제외 조건이 충돌하거나 모두 제외된 날은 강제 배정 대신 중단한다.

## 적용 및 검증

웹과 Firebase Functions는 `functions/schedule.js`를 함께 사용한다. 웹, Functions, Firestore 보존 규칙을 함께 배포해야 한다. 코드 배포만으로 현재 일정이 바뀌지는 않는다.

관리자 화면에서 **일정 미리보기**로 횟수·요일 표를 확인한 뒤 **미리보기 일정 적용**을 누른다. 미리보기 이후 일정이 달라지면 저장하지 않는다. 전체 이력 초기화 기능은 제거했다. 메인 화면은 조회만 하며 빈 일정을 자동 생성하지 않는다.

검증: `npm test`, `npx tsc --noEmit --incremental false`, `npm run build`.
운영 연결 설정과 미리보기인 `docs/*.txt`는 Git에서 제외한다.
